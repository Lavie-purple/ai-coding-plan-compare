不要把「订阅为 API 的 1%」理解成可以随便用。该比值衡量的是额度套利空间，不是可用自由度：订阅额度受 5 小时窗口、周上限、并发数、可用工具白名单多重限制， 且明确禁止接入第三方 Agent（部分平台直接写明违规即中止）。厂商之所以乐于给出 1% 的比值，正是因为这层限制让绝大多数用户跑不到上限。

规律：订阅折扣的本质是「批发」。用量越接近额度上限，折扣越大（智谱官方称最高省 87–90%）；用量远低于上限时，按量付费反而更划算。 关键风险是多数平台不支持退款、额度不结转，因此「买最低档实测一个月 → 按需升级」永远优于直接上高档。

六、测算方法论（可复现）

本表「折合 Token/月」由统一工作量模型反推，而非厂商公布值。模型参数： tokensPerRequest = 120,000、outputRatio = 0.005、cacheHitRate = 0.95。 做法是：以「最优可用模型」为基准，按官方倍率表或实测数据把请求数 / 积分 / Credits / AFP 折算为 token 总量。

数据类型在测算中的权重说明
实测（measured）最高有真实调用记录支撑，如 Claude Opus 5、GLM-5.3 各档
倍率换算（multiplied）中高官方给出倍率但未给绝对值，如字节方舟 Coding Plan
计算（calculated）中按官方计价规则 + 工作量模型推导
按请求换算（calculatedRequests）中低官方仅给 prompt / 请求数，按 1 prompt ≈ 15 次请求折
未公开（unknown）——本表 token 列为空，仅保留价格供参考

「¥ / 百万 token」= 连续包月价（折人民币） ÷ 折合月 token 量，由脚本计算；档位阈值：≤¥0.15 优、¥0.15–0.35 中、>¥0.35 差。

为什么有 52 档留空

平台级在售的 108 个订阅档中，只有 56 档能折算为 token。留空的 52 档集中在以下几类——它们的官方计量单位与 token 之间缺少公开的换算桥梁， 强行折算会得出看似精确、实则无据的数字，因此本表选择留空并在「官方用量口径」列保留原始单位。
口径区分：「平台级在售」取自数据源 platforms.json（平台整体是否在售）， 「套餐级停售」取自每个套餐自身的 discontinued 标记。二者独立——例如京东云平台状态为「限量」，但其 Coding Plan 旧档已停售。
