自定义排序怎么用

点任意表头即可排序，再点一次翻转方向。需要「先按性价比档位、再按月费」这类多级排法时，点工具栏里的「排序」按钮自己配规则链：从上到下依次生效，可增删、可调优先级，也能一键套用预设（性价比优先 / 在售优先 / 按平台分组等）。 两条口径值得知道：枚举列按语义序（优→中→差、在售→限量→暂停→已下架→未收录），不是按拼音；缺值恒排末位，与升降序无关 —— 否则降序时「没有报价」会被顶到最前，看着像最贵。 你配的规则会记在本机浏览器里（弹层右下角可一键恢复默认），换台机器或清缓存则回到默认的「月费升序」。

「官方页」列是什么

这一列取代了上游数据集的「跳转链接」列。上游给每个套餐配的那条链接里，129 条中有 107 条是指向第三方短链服务的推广链接（带厂商定制的邀请码，同一平台上还夹着加群、成品号之类的内容）。本报告不在页面上放推广链接，一律改写为厂商官方定价 / 订阅页，并剥掉了全部邀请与跟踪参数。 两条口径：显示域名、点击新窗口打开（带 noopener noreferrer nofollow）；拿不准的宁可空着 —— 无可确证官方页的档位显示「—」，不做兜底猜测，已下架且官方活动页随之撤下的档位同样留空。

价格列怎么读：促销价 ≠ 长期成本

「月费 ¥」列在不同行并不总是同一个口径，价格单元格下方的小字是你的判据：「首期 ¥N」表示首个周期更便宜、之后回到月费（月费本身就是长期价）；「原价 ¥N」/「NN% OFF」表示当前填的是促销价，续费会涨回去 —— 这类行（本期 10 行）会在下方额外挂一条「续费 ¥N」，就是促销结束后的常态月费，也同步写进 CSV 的「稳定价(¥)」列。 CSV 里「稳定价(¥)」留空 = 与「月费」同值（不是「未知」）；按长期成本比价时，用「稳定价(¥)」而非「月费 ¥」更稳妥。

「—」是什么意思（空值口径）

「¥/百万 token」与「档位」两列本期覆盖 24 / 280 行，其余行显示「—」——它的含义是该指标不适用，不是「最差档」。原因是这些档位用积分 / Credits / AFP / 燃料值 / 请求次数计量，官方普遍不公布单位间的倍率表，硬折算等于编数字，所以留空不臆造。 同一套「—」规则也用于「官方页」（无官方页可指）与按量 API 行的档位列（无订阅档位概念）。CSV 里空值一律是「—」或空串，没有第二种写法，可以安全地当作「不参与比较」筛选掉。

同模型跨渠道比价，有两点先看清

① 单价低 ≠ 额度够用：同一模型的低价渠道，月 token 可能只有几千万（够轻度用），重度 Agent 场景要结合「月 token」列看，别只看单价。 ② 谷/峰是两个真实档位：像智谱那样谷时 50% 抵扣的套餐，同一档位会出现谷 / 峰两条，价差恰是抵扣系数；错峰能省一半，但没条件错峰就别按谷时价预估成本。

测算方法论（可复现）

Methodology

本表「折合 Token/月」由统一工作量模型反推，而非厂商公布值。模型参数： tokensPerRequest = 120,000、outputRatio = 0.005、cacheHitRate = 0.95。 做法是：以「最优可用模型」为基准，按官方倍率表或实测数据把请求数 / 积分 / Credits / AFP 折算为 token 总量。

数据类型在测算中的权重说明
实测（measured）最高有真实调用记录支撑，如 Claude Opus 5、GLM-5.3 各档
倍率换算（multiplied）中高官方给出倍率但未给绝对值，如字节方舟 Coding Plan
计算（calculated）中按官方计价规则 + 工作量模型推导
按请求换算（calculatedRequests）中低官方仅给 prompt / 请求数，按 1 prompt ≈ 15 次请求折
未公开（unknown）——本表 token 列为空，仅保留价格供参考

「¥ / 百万 token」= 连续包月价（折人民币） ÷ 折合月 token 量，由脚本计算；档位阈值：≤¥0.15 优、¥0.15–0.35 中、>¥0.35 差。

为什么有 52 档留空

平台级在售的 108 个订阅档中，只有 56 档能折算为 token。留空的 52 档集中在以下几类——它们的官方计量单位与 token 之间缺少公开的换算桥梁， 强行折算会得出看似精确、实则无据的数字，因此本表选择留空并在「官方用量口径」列保留原始单位。 口径区分：「平台级在售」取自数据源 platforms.json（平台整体是否在售）， 「套餐级停售」取自每个套餐自身的 discontinued 标记。二者独立——例如京东云平台状态为「限量」，但其 Coding Plan 旧档已停售。
